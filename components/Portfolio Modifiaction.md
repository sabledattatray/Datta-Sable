Every featured case study must include:

A. Project title written for humans and search intent. B. Project type
and truthful status. C. One-line summary of the business question

reporting friction existed? - Is this a real business engagement,
personal exercise, or simulated scenario? E. Dataset: - Source and

Whether data is public, synthetic, anonymized, or confidential - Known
data-quality limitations - Never expose personal, client-confidential,
or sensitive data. F. Tools: - Only technologies actually used - Explain
their roles, e.g. Power Query for transformation, DAX for measures, SQL

preview - Captions describing what each screenshot proves - Optional

changed over time? Which regions/products are contributing? Where are
exceptions? Which categories need attention? - Answers must come from
actual analysis, not fabricated generic claims. J. Findings: - Report
only insights supported by the data and calculation. - If using
illustrative data, label the insight as illustrative. K. Outcome: -
Quantify only if there is a defensible before/after measurement. -
Otherwise describe the deliverable without inventing savings, percentage
improvements, ROI, or business impact. L. Limitations and next steps: -
State what the analysis cannot prove. - Suggest a sensible next
iteration. M. Links: - Live demo only if accessible and working -
Repository only if it exists and is safe to share - Download only if the
file is real, clean, and safe - Contact CTA for similar work.

Use a concise summary card near the top: - Business question - Dataset /

Do not fabricate testimonials, client logos, client names, employment

documented and approved for publication, remove it. If a project is

======================================================================

Goal: Premium, calm, credible business intelligence portfolio. It should
feel like a polished analytics consultant’s site, not a flashy cyberpunk
template or a generic AI-generated landing page.

Design rules: - Inspect current site tokens, fonts, colours, logo,
header, footer, animation system, and responsive breakpoints first. -
Preserve brand elements that are working unless there is a clear
usability issue. - Use a restrained palette: deep navy/charcoal,

imposing a new palette. - Strong typography hierarchy; readable line

stock images as fake dashboard evidence. - Use screenshot frames with
captions, not decorative screenshots that are impossible to read. - Use

empty hero areas. - Use subtle motion only where it supports
comprehension; respect reduced-motion preferences. - Keep body text
comfortably readable and contrast accessible. - Buttons and links must
have visible focus states. - Do not rely on colour alone for status or
category. - Make touch targets comfortable on mobile. - Provide loading,
empty, error, and success states for interactive controls. - Avoid
layout shift from images: set width/height or aspect ratio and lazy-load
below-the-fold media.
