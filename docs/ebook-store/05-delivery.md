# Phase 5 — private fulfillment

Paid PDFs use the existing private Vercel Blob store and server-only COMMERCE_BLOB_READ_WRITE_TOKEN. Admin-only uploads store a random private path with hash/bytes/filename/version; upload responses never return a public paid-file URL. No eBook PDF has been uploaded or committed in this session. Malware scanning is not available; do not claim it occurs. Validation of the PDF header is not malware scanning or proofreading.

Account buyers use their verified account. Guest buyers request a neutral-response email link before purchase, then explicitly consume it by POST. Random-ID/HMAC links expire after 30 minutes, are single-use, and are stored hashed. A resulting random, hashed, HttpOnly/SameSite=Lax session lasts 24 hours (Secure in production). Email/IP-hash quotas use shared DB limits. Guest identity is normalized verified email; purchase/history queries constrain ownership. Access mail is queued, leased and retried; uncertain provider outcomes require review rather than blind resend. No invented sender address is introduced for access mail.

The library displays only the buyer's orders and verified active entitlements. It mints random hashed five-minute grants with at most three exchanges. Download exchanges recheck PAID, ACTIVE, delivery readiness, expiry/revocation/use count, and atomic use allocation; only then issue an exact-path private URL valid for one minute. Grants retrieve the order item's immutable resource snapshot, including historical assets retained after replacements. Download events reuse CommerceDownload, with hashed guest identity. Revocation and full refund deny new signed links; already issued one-minute URLs can remain usable until expiry.

Tokens are transported in URL fragments, immediately removed from history, then sent in POST bodies. Token-bearing API responses are private/no-store, no-referrer and noindex. Private eBook views are excluded from visit analytics, Google analytics initialization and third-party convenience widgets. The library offers logout of the guest session. Receipt links for guest orders point to the library, where another email link can be requested. Email acceptance is never presented as inbox delivery.

The daily worker deletes expired token records after a day and expired grant/mail records after 30 days. Existing financial/download/audit records use the site's existing retention policy; a dedicated retention job for download/audit history is still an operational requirement. EBOOK_ACCESS_SECRET rotation invalidates outstanding link derivations: drain/review pending email jobs first, then rotate and tell buyers to request fresh links. Keep old private PDFs and DB snapshots in protected backups; verify restore using hashes.

Still blocked: real private store configuration/access test, uploaded PDF checksum/open verification, verified sender delivery test, full guest purchase E2E, backup/restore rehearsal and a frequent scheduler. Do not publish until those pass.
